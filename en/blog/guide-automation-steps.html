Connect actions into a flow: Create a "record and auto-save" multi-step macro

Expand basic text keys into an automated process, connect text input, anti-collision delay and ⌘S shortcut key, and use actual testing and preview to ensure stable execution of each step.

September 10, 2026

After memorizing a sentence, do you still have to manually press the shortcut key to save it? In fact, just pack multiple actions into the same button. This tutorial will take you to expand a single step into a complete macro of "enter text → pause for 0.5 seconds → automatically press ⌘S". Through mobile phone preview and practical trial operation, you can master the core logic of multi-step automation.

Picture description:The screenshots show the three steps of real editing in the app and the content preview. The Mac connection status is demo data. The preview does not press ⌘S and does not prove that the file has been saved; the actual saving results need to be checked in your own Mac document.

Before starting

  • First read the tutorial on common text buttons and create a "Send Text" button.
  • Prepare a test document on your Mac that has been saved to disk, and confirm that the software saves it with ⌘S; place the cursor in the editable text.
  • Connect to the Mac Automation Service; keep "Run Once" for the first exercise to avoid multiple rounds of input that are difficult to judge.

1. Expand from text buttons to automation

Open a configured text button in the desktop editing state, and set the input content to "Today's record: confirm the goal first, then add the next step." After input, keep "No additional keys". Close the text editing page, return to the operation configuration panel, and click "Expand to Automation".

The newly opened "Edit Automation" page will automatically retain the original text steps. Enter "Record and Save" in the "Automation Name" field. This allows you to add subsequent steps from an already defined action without having to retype the entire paragraph.

Reference:Complete steps to create commonly used text buttons。

2. Add a "wait 0.5 seconds" step

Click "Add step" under "Steps" and select "Wait". The default waiting time for a new step is 0.5 seconds. This example uses this recommended default value directly; if changes are needed, click "Wait 0.5 seconds" to enter the step editing page for fine-tuning.

The list of steps at this time is "Enter text" and "Wait 0.5 seconds". The waiting time is fixed and will not detect whether the target software has been loaded. Appropriate delay waiting can effectively prevent the key conflict caused by the text of the previous step not being fully received by the editor and the shortcut keys of the next step being triggered in advance.

3. Add Command-S save shortcut key

Click "Add Step" again, select "Shortcut Key", and then open the newly added shortcut key step. Select "Command" in the key combination area, fill in S in the primary key input box, and complete the input.

Return to the automation editing page and check that the key values displayed in the third step strictly correspond to Command and S. The key combination is sent to the current foreground application of the computer when this step is performed, so the test document needs to be kept in the foreground; the first save as dialog box will change the subsequent process. It is recommended to create and save the test file on Mac first.

4. Confirm the sequence and set it to "Run Once"

Go back to the step list and double-check the order of the steps: Step 1 is "Enter text," Step 2 is "Wait 0.5 seconds," and Step 3 is "Command + S." Select "Run once" as the execution mode.

If you add extra steps by mistake, you can use the editor's editing mode to delete or drag and move steps, or you can use the "Undo" button at the bottom to restore recent modifications; if you need to temporarily skip a step, enter the step and turn off "Enable this step".

5. Preview the content and try it out on Mac

Click "Preview Content" and check whether the descriptions of the exercise text, wait 0.5 seconds, and save shortcut keys are accurate one by one. Close the preview after confirming that there are no redundant Enter or blank steps.

When connecting to the automation service, you can click "Try Run Once". It saves the configuration and actually executes a round on the Mac's current application. Bring the test document to the foreground before triggering the test run; a record should be inserted and processed by the target software ⌘S. Finally, check the document content and the save status of the software, and if necessary, close and reopen the test file to confirm.

6. Save button, used in daily documents

After confirming that the trial run results are as expected, click "Save and Sync" to exit component properties and desktop editing mode. Then just tap the automation button on the mobile phone's sub-controller to complete log appending and instant saving with one click.

For use with other professional software, you can gradually add "switch applications" or more shortcut keys. A trial run is performed for each new step. It is easier to troubleshoot positioning problems than adding a large number of actions at once. First use clear text and shortcut keys to complete a stable small process, and then gradually expand it.

FAQ

Why does the "Save As" window appear after running it?

The test file has not completed its first save, or the target software uses ⌘S for other commands. Save the file manually first, confirm the software's shortcut key behavior, then return to the text and try again.

Even after adding wait, why is the word still entered at the wrong position?

Waiting only pauses for a fixed duration and does not correct focus. Check the Mac foreground application, document body, and pop-up windows; when you need to switch applications, you should explicitly configure the "Switch Application" step.

There is command,s in the preview, why is the file not saved?

The content preview shows step descriptions and does not execute shortcut keys. It is necessary to test run after connection and confirm the saving result in the target software.

How do I stop an automation that is running repeatedly?

The editor provides Stop Automation during runtime; Stop Automation can also be configured as a separate button. The first exercise remains "Run Once" without enabling repeat mode.
